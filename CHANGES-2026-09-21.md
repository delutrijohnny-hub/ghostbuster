# Changes — 21 Sep 2026

## Live now (browser only — no deploy needed)

Reload the app and these are active.

**1. Client timezones were our timezone, not theirs.**
`supabase/functions/_shared/parse.ts` stored `ev.start.timeZone` as the client's
zone. That field is the *organiser's* calendar zone — ours, or `Asia/Kolkata`
for events a teammate abroad created. Every synced client inherited it, and
`renderTemplate` used it for `{time}`, so a California client booked at 2pm
Eastern was texted "2:00 PM". The area-code lookup the app was designed around
(`timezoneForClient`) was never called on the hosted sync path at all.

- `logic.js` → new `resolveClientTimezone(raw)`, used by `sanitizeClient`.
  The area code wins; a stored zone is only trusted when `timezoneConfirmed`
  is set. Existing wrong rows self-correct on load and are written back on the
  next save.
- `app.js` / `hosted/app.js` → picking a zone in the client modal now sets
  `timezoneConfirmed`, so a deliberate correction stops being overridden.

**2. Area code corrections.**
- `915` (El Paso) was Pacific → Mountain.
- `219` (Gary, IN) was Eastern → Central.
- Added Alaska (`907`), Hawaii (`808`), and `239 / 727 / 947 / 656`.

**3. Times now carry a zone label.** `{time}` renders "11:00 AM PDT" — DST-correct,
straight from `Intl`.

**4. Day-of texts send the real Meet link.**
Google puts the Meet room in `X-GOOGLE-CONFERENCE` / `LOCATION` (.ics) and
`hangoutLink` / `conferenceData` (API). Both parsers only read the *description*,
and these booking-form descriptions never contain it — so `meetLink` was always
empty and `logic.js:498` fell back to `'the link in your calendar invite'`.

- `parseICS` now reads `LOCATION` and `X-GOOGLE-CONFERENCE`.
- New `meetLinkFromEvent(ev)` checks conference → location → description.
- `extractMeetLink` also matches Teams and Whereby.
- The calendar fallback is gone. If a link is genuinely missing the text reads
  `(no link on file — paste one before sending)` so it can't ship unnoticed.

## Needs a deploy

`supabase/functions/_shared/parse.ts` and `.../google-calendar-sync/index.ts`
are updated but not deployed. Until you run this, new bookings still get the
wrong zone written underneath — the browser fix corrects them on load, so you
won't see it, but it's worth doing.

    supabase functions deploy google-calendar-sync

Changes in there: timezone derived from the phone's area code with the event
zone only as fallback; Meet link read from `hangoutLink` / `conferenceData` /
`location`; and re-sync no longer overwrites an existing timezone, so a
hand-correction survives.
